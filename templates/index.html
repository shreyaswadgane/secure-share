🔐

Envelope Encryption

Each file receives an ephemeral 256-bit Fernet key (DEK) that is encrypted with the master key (KEK). File contents are never stored in plaintext on disk or in the database.

👥

Targeted Peer Sharing

Specify authorized recipients by email or username. Only the intended recipient can access and trigger on-the-fly decryption of the shared payload.

⏳

Self-Expiring Shares

Set customizable expiration windows (1 hour, 24 hours, 7 days, 30 days) to prevent permanent access to sensitive data.

🔢

Download Quotas

Enforce one-time downloads or strict quotas. Once the download quota is fulfilled, the link is permanently locked.

Secondary Password Lock

Add an extra layer of protection by attaching a secret passphrase to your file share that the receiver must provide before downloading.

Tamper-Proof Audit Trail

Track who uploaded, downloaded, or revoked files with timestamps and IP activity logging for accountability.

🔬 Cryptographic Pipeline Overview (Project Viva Reference)

1. Upload & DEK Generation When a user uploads a file, the server generates a cryptographically secure random Data Encryption Key (DEK) via Fernet.generate_key().
2. AES-128 Encryption & UUID The file bytes are encrypted in memory. The ciphertext is saved to disk under a non-guessable UUID filename (e.g., 9e2b4...enc).
3. Master Key Envelope The DEK is encrypted with the MASTER_ENCRYPTION_KEY from .env and saved into the database's encryption_key_ref column.
4. On-the-Fly Decryption Upon authorized download request, the DEK is decrypted, ciphertext is read, decrypted in RAM, and streamed directly without ever writing plaintext to disk.
